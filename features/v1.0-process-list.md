# v1.0 — Process list, ports and project grouping
Owners: planner → designer → electron-main → frontend → motion → reviewers → qa → log

## Goal (plain)
Show my running dev processes, what port each uses, and which project each belongs to.

## Acceptance criteria
- [ ] Lists allowlisted processes for the current user with name, port(s), CPU %, memory, uptime
- [ ] Groups by project root (walk up from cwd to the nearest `.git` or `package.json`, stay inside home)
- [ ] Search filters by name, port, project
- [ ] Auto-refresh every 3 s (setting: 2/3/5/10 s); pauses when window hidden; no overlapping refreshes
- [ ] Skips `.app/Contents/` executables and the user ignore list
- [ ] Empty state, loading state, and error state exist
- [ ] Rows show state text, not color only; "Details" reveals pid, full command (masked by default)

## Technical notes
```bash
ps -U "$USER" -o pid=,ppid=,pcpu=,rss=,etime=,command=          # rss is KB
lsof -a -d cwd -Fpn -p 123,456                                    # cwd per pid
lsof -iTCP -sTCP:LISTEN -nP -Fpn                                  # listening ports
```
- lsof exits non-zero when a pid disappears; treat stdout as valid.
- Get the executable name reliably (paths may contain spaces): parse `comm`/first token carefully and unit-test with a fixture that has spaces.
- `ProcessProvider` interface with a darwin implementation (see `docs/02-architecture.md`).
- Convert etime (`dd-hh:mm:ss`) to seconds in a pure function.

## Design notes
Group header = folder name + path in muted mono. Row = name, ports, cpu, mem, uptime, Stop button (quiet).
One primary action on the screen: "Stop all dev processes" is a quiet button; danger styling only inside the confirm dialog.

## Out of scope
Killing (next spec), Docker, alerts.
