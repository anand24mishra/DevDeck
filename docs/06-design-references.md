# 06 — Design references (study, do not copy)

References the human curator chose. Agents cannot rely on browsing them live, so the human captures
screenshots into `docs/references/` and notes what to learn. Never reproduce another site's layout,
copy or assets; extract principles only.

| Source | Use it to learn |
|---|---|
| dribbble.com | Density, iconography, dark UI details for tools and dashboards |
| siteinspire.com (e.g. "Direct" / wearedirect.co) | Strong typographic hierarchy, restrained layouts, confident whitespace |
| footer.design | How to end a page/screen: small details, quiet calls to action |
| awwwards.com | Motion pacing and interaction craft (then reduce it — this is a utility) |
| ui.aceternity.com templates | Component ideas and motion patterns; do not import as-is (busy, template look) |
| impeccable.style | Design vocabulary and the 61-check slop detector we run on our UI |

## How to use
1. Pick 3–5 screens (not whole sites). Save PNGs to `docs/references/` with names like `dense-list-dark.png`.
2. For each, write 2 lines in `docs/references/README.md`: what to learn, what to avoid.
3. Designer agent reads those notes plus `DESIGN.md`, then proposes 2 directions before building.
4. Human picks one. Record the choice in `DESIGN.md`.

## What we take from "techy"
Monospace for machine values, hairlines, restrained palette, small caps labels used sparingly.
What we avoid: neon glows, terminal cosplay, fake "hacker" scanlines, gratuitous grids.
